## Phase 5 — current backend inventory (2026-08-20)

- Repository migrations are not a complete schema history: 6 migrations exist, while the checked-in live-schema snapshot describes roughly 336 tables and 140 functions/triggers.
- The frontend directly references 55 database tables and 3 storage buckets (`uploads`, `user-images`, `user-music`).
- Only `anything-api` exists under `supabase/functions`, while the frontend invokes about 20 additional deployed Edge Functions whose source is not present in the repository. These functions must be exported and audited before backend cleanup.
- Roughly 280 tables are not directly referenced by the current frontend, but this does **not** prove they are unused: cloud-only functions, bots, or other clients may use them.
- No database or Edge Function deletion is safe until production telemetry, other-client ownership, and a rollback export are confirmed.
- `anything-api` uses `verify_jwt = false` and performs its own authentication; wildcard CORS should be narrowed after confirming all production origins.
- A frontend `.from("uploads")` reference may confuse a database table with the identically named storage bucket and needs focused runtime verification.

### Backend cleanup gate

1. Export every deployed function into source control.
2. Collect read/write/invocation telemetry for at least one representative usage cycle.
3. Map every unreferenced object to other apps, bots, triggers, and cloud-only functions.
4. Back up before any destructive migration.
5. Require explicit approval for each named table/function removal.
